# Carta de notificação (PDF editável) no MAPA-PRO — design

2026-10-09. Status: implemented with this spec (prompt:
`docs/prompts/carta-notificacao.md`).

## What

A **Carta** button on every row of the **Domicílios** tab of the MAPA-PRO
panel, on both pages (Último Movimento and Relatório de Acompanhamento de
Biomarcadores). One click downloads `carta_<controle>_<domicilio>.pdf`: a
one-page A4 notification letter to the resident, prefilled from live SIGC
data, with every variable part an editable AcroForm text field.

## Why

Supervisors leave a printed notice at households that several visits
failed to reach. The letter used to be produced outside SIGC
(pns.zonas) from a nightly snapshot, so the agent named on it drifted.
The panel already has the live holder of every household and the
address of the filtered recorte; the letter belongs there.

## Pieces

| File | World | Role |
|---|---|---|
| `extension/features/carta-notificacao/carta-notificacao.js` | MAIN | button handler, data assembly, PDF drawing, download. A **local-resource** directory for the privacy gate: loads the two vendored scripts, never requests anything. |
| `extension/features/usuario-lookup/usuario-lookup.js` | MAIN | siape → cadastro, two same-origin requests, 60 s in-memory cache. A **fetch** directory for the gate. |
| `extension/features/ultimo-movimento-map/ultimo-movimento-map.js` | MAIN | renders the Carta column (both variants), wires the click to `window.__sigcProCarta.gerarCarta`, carries the address columns on the joined row, drops the column from the CSV and the filter row. |
| `extension/features/ultimo-movimento-map/ultimo-movimento-map-relay.js` | ISOLATED | writes `data-sigc-pro-pdf-lib-js-url` and `data-sigc-pro-carta-assets-js-url` on `<html>` (same mechanism as Leaflet). |
| `extension/features/agenda-lookups/agenda-lookups.js` | MAIN | `tableToEnderecosMap` now also carries logradouro, número, complemento, bairro and Biomarcadores (optional columns, blank when absent). |
| `extension/common/sigc-common.js` | MAIN | `USUARIO_ORIGIN_HEX`, `USUARIO_CODIGO_PESQUISA`, `usuarioGatewayUrl`. |
| `extension/vendor/pdf-lib/pdf-lib.min.js` | — | pdf-lib 1.17.1, unmodified (`VERSION` has the sha256). |
| `extension/vendor/carta-assets/carta-assets.js` | — | the IBGE logo+wordmark and the Brasão da República as base64 PNGs, one global. Generated by `scripts/gen-carta-assets.mjs` from the pns.zonas SVGs. |

Two directories instead of one because the gate's directory classes are
exclusive: a fetch directory may not assign a script source, and a
local-resource directory may not call `fetch`. The lookup exposes one
global (`window.__sigcProUsuarioLookup.lookupUsuario`) that the carta
feature calls on click.

## Data per letter

| Field | Source |
|---|---|
| controle, domicilio | the joined row |
| endereco, complemento, bairro | Lista de Endereços columns, via `enderecosMap` → joined row. Número `0`/empty → `S/N`; a complemento starting with `SN ` drops that token. Title-cased. |
| municipio | `municipioFromControle` (`SALVADOR - BA`) → `Salvador/BA` |
| controle's UF | first two digits of the controle (the filter's `IdUf` only as fallback) — picks the Superintendência phrase |
| biomarcadores | Lista de Endereços column; `Sim` → the two-stage paragraph, anything else → the interview-only paragraph |
| agencia_descricao | the report row's Agência (always on the biomarcadores page; on Último Movimento when the live table has the column, read optionally by label) → the cadastro's posto (the live cadastro has none) → the filter's agência: the page's `#IdAgencia` option text when the profile has the selector, else the UF's list from `/Filtro/CarregarAgencias` (fetched by ultimo-movimento-export, cached per UF). A filter by município or controle has no agência → blank, for the issuer to fill |
| nome, siape | the row's Entrevistador, `"<siape> - NOME"`; a bare value is a name with no siape (no lookup) |
| cargo_descricao, celular_pessoal, email_institucional | the cadastro; blank when the lookup failed or was skipped |

Title case is a port of `orce::ToTitleCasePT` (lower-case particles when
neither first nor last word; well-formed Roman numerals upper). Phone:
`+55DD########` → `(DD) ####-####`, `+55DD#########` → `(DD) #####-####`,
anything else verbatim.

## Usuário lookup

Host `w3servicosigc.ibge.gov.br`, behind the same F5 gateway as the page.
The gateway prefix is `/f5-w-<hex>$$` where hex is that origin's bytes
in lowercase hex — the same encoding `f5Prefix` decodes for the page's
own host. The request still goes to `location.origin`; this is not a
third-party URL. The hex lives in `extension/common` (exempt from the
gate's no-absolute-URL rule) because the feature directory may not
contain `https://`.

1. `POST /usuario/Grid`, `X-Requested-With: XMLHttpRequest`, form body
   `CodigoPesquisa=PNS2025&Nome=&…&Login=<siape>&StatusUsuario=true`.
   HTML table; cells mapped by `thead th` text (the action column comes
   and goes with permissions); the user **id** is the `value` of the
   row's action `<button>`; empty table → unknown siape.
2. `GET /usuario/EditarUsuario?codigoPesquisa=PNS2025&id=<id>`. HTML
   form; fields read by input name/id first, label text second; a
   missing field is blank, never an error.

`codigoPesquisa` is `PNS2025` (verified live) — not the report pages'
PNS2026, hence a separate constant. Both requests set `referrer:` in the
fetch init (a same-origin URL; `Referer` is a forbidden header name and
would be dropped silently) — the same approach `postRelatorio` uses.

Cache: a `Map` siape → `{at, record}`, 60 s, page lifetime, promise
shared between in-flight clicks, rejection evicted. One siape per click;
never prefetched. On failure the letter is still produced with nome and
siape from the row and a toast.

**Session.** The usuário module has its own session, separate from the
report pages'. Without one, the Grid POST does not answer with a table:
the gateway returns the OpenID Connect "Working…" page — a form of
hidden inputs that a script submits to the SIGC authentication service
(confirmed live 2026-10-09; fixture
`tests/fixtures/usuario-grid-auth-redirect.html`). The lookup never
posts that chain itself (a fetch-based attempt was tried and dropped:
the sign-in needs a real navigation, and it is the user's act). It
recognises the page, or a login form, and rejects with
`ErroAutenticacao` (`code: 'auth'`, `loginUrl` = the module's index
through the gateway). The carta feature then opens that URL in a tab
(`window.open`, inside the click), lets the browser run the sign-in
redirects as any tab would, and retries the lookup every 2 s for up to
90 s. When the lookup answers, the tab is closed and the letter carries
the cadastro; when the user closes the tab, the poll stops; on timeout
or a blocked popup the letter is produced without the cadastro and a
toast links to the module. Not cached: a later click retries.

On the direct host (no gateway prefix, e.g. via VPN) the lookup falls
back to `location.origin`, which does not serve the usuário module; it
fails and the letter comes out without the cadastro. Reaching the
module's host directly would need a third-party URL, which the gate
forbids by design.

## PDF

pdf-lib, Helvetica/Helvetica-Bold (WinAnsi — a test asserts every
static string encodes; `Decreto-Lei` keeps a plain hyphen because the
word wrapper splits on spaces only and U+2011 is not WinAnsi). A4,
margins 2.2 cm sides, 1.6 cm top, 1.8 cm bottom. Text fields are 10 pt,
dark blue `#004282`, no border; a value that would overflow its box
shrinks (never below 7 pt) instead of being clipped. Appearance streams
are generated by pdf-lib; the AcroForm gets a `DR` naming both fonts so
a viewer regenerating a field after an edit finds them. pdfMake, which
the page already loads, cannot create form fields.

Layout, top to bottom: letterhead (logo, `SUPERINTENDÊNCIA ESTADUAL DO
IBGE <prep> <UF>`, rule); brasão + `SERVIÇO PÚBLICO FEDERAL` on one line, red
`URGENTE` box; title; destinatário block (left rule, grey labels, two
columns); `saudacao` field (bold 11 pt black, default `Prezado(a)
morador(a),`); five justified 11 pt paragraphs (paragraph 2 by the
Biomarcadores flag); the agent box (78 % wide, `#f2f6fb`, six fields labelled Nome/Matrícula/Função/Telefone/E-mail/Agência);
`Atenciosamente,` + the Superintendência line in bold — no signature, no
person's name; footer rule, Superintendência left, `www.ibge.gov.br ·
0800 721 8181` right. The static layout is fixed; a guard throws if it
ever reaches the footer.

Field names, exactly: `saudacao`, `endereco`, `complemento`, `bairro`,
`municipio`, `controle`, `domicilio`, `nome`, `siape`,
`cargo_descricao`, `celular_pessoal`, `email_institucional`,
`agencia_descricao` (the pns.zonas letter's names) and, below three blank lines left for a signature or stamp, two editable closing lines: `assinante` (blank) and `superintendencia`.

## UX

- Last column of the Domicílios table, both variants; excluded from the
  CSV and from the per-column filter row like the pin column.
- Click: button disabled → lookup (cached) → vendored scripts loaded on
  first use → build → download. Status line in the Domicílios toolbar:
  `Gerando carta <controle>/<dom>…` then `Carta <controle>/<dom> gerada
  para <nome>` or `… gerada sem agente`.
- Toasts: cadastro not read; household without address (letter with the
  address fields blank).
- No batch button, no viewer. One click, one file.

## Privacy

Two new same-origin requests, only on click, sending a siape and
receiving that user's cadastro; nothing stored. `check-privacy.sh`:
`usuario-lookup` added to `FETCH_DIRS`, `carta-notificacao` to
`LOCAL_RESOURCE_DIRS`; the self-test plants an absolute URL and a
script-source assignment in the fetch directory, and a `fetch(`, a
non-`.jsUrl` source and an absolute URL in the local-resource directory
(all must fail), plus the sanctioned `.jsUrl` load (must pass).
`manifest.json` lists both vendored scripts as web-accessible resources.

## Review (2026-10-09, clean session)

Fixed from the review: Grid row matched on the siape, not the first row;
the sign-in poll survives transient HTTP errors; field values outside
WinAnsi become `?` instead of failing the letter; the row's siape and
the Grid row's name win over the form; the form parser is scoped to the
form holding the hidden Id and ignores unselected selects; agência
precedence is row → filter → cadastro; a null lookup (unknown or
inactive siape) gets its own toast; `redirect: 'manual'` so a redirect
is "no session", never followed; Roman numerals limited to i/v/x and
`(`/`'` as capitalisation boundaries; número `SN`/`S N` → `S/N`; the
agência list is requested only when the row has no agência; address
columns resolve one by one; the tile-host allowlist applies to the map
directory only (self-test 28). Left as is: `window.open` without
`noopener` (same-origin via the gateway; `noopener` returns no handle
for the closed-tab poll).

## Known gaps

- `tests/fixtures/usuario-editar.html` is **synthetic** — written from
  the expected ASP.NET MVC form shape, not captured from the live
  module. The parser tries input names/ids first and label text second,
  so either convention parses; replace the fixture with a sanitized
  capture when one is taken and keep the values.
- The Grid fixtures are likewise shaped from the prompt's description of
  the live table (columns, button `value` = id), not a capture.
- The usuário module's own sign-in page (and whether its `Login=` filter
  is exact or prefix) was not captured; the parser now requires an exact
  Matrícula match either way.
